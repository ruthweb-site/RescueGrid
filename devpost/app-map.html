RescueGrid — App Map & Architecture Tour

Disaster Relief Emergency Operations Center (EOC) Triage & Allocation Console

Snapshot: Post-Build / Pre-Ship

1. Overview

RescueGrid is a local disaster relief command dashboard. When an incident commander selects a disaster scenario (e.g., River Flood or Cyclone) and resource stocks, RescueGrid does two distinct things:

  • Deterministic Core: Calculates exact risk scores (0–100), community triage ranks, and prioritizes resource distribution (rations, medical kits, water purification units) with explicit shortfall math.
  • AI Action Briefing: Uses Google Gemini to generate high-level operational briefings while strictly validating and hydrating computed figures to prevent hallucination.

3. Reference Route: 3 Key Stops

Stop 1: The Deterministic Scoring Engine

src/engine/scoring.js (function calculateCommunityRisk)

Computes risk scores using a weighted sum of hazard severity, road cut-off penalty, vulnerable population ratio, and medical urgency. It breaks ties predictably by population size, guaranteeing reproducibility.

Stop 2: Priority Resource Allocation & Shortfall Logic

src/engine/allocation.js (function allocateResources)

Sorts communities by priority score and allocates available supplies greedily. Any unfilled need is tagged as an explicit shortfall gap (e.g., 200 rations short), visualized directly on the allocation dashboard.

Stop 3: Resilient AI Proxy & Guardrail

server.js (endpoint /api/brief) & src/services/aiBriefing.js

Calls gemini-3.1-flash-lite with exponential backoff retry. It passes the deterministic rankings to the model and validates the JSON output with strict fallback handling if the API is unavailable.

4. To Change This, Start Here

  • Add a new community or road route: Edit src/data/district.json.
  • Tune risk scoring weights: Edit WEIGHTS in src/engine/scoring.js.
  • Adjust AI prompting or model configuration: Edit CALL_GEMINI in server.js.
  • Change theme or map styling: Edit CSS variables in styles/main.css.

5. A Practice to Reuse

Separation of Deterministic Calculations from LLM Synthesis

In high-stakes applications (like disaster triage), never ask an LLM to calculate scores, rank orders, or distribution math. Instead, compute all math deterministically in local functions tested with unit tests (tests/engine.test.js). Then, provide the calculated summary to the LLM solely for executive summarization, backed by automatic offline fallbacks (src/engine/templatePlan.js).
